# FLOTA — Design Context

## Users

**Usuario principal**: Administradores de flota vehicular (dueños de empresa, jefes de operaciones, encargados de pagos). Usan la app diariamente desde desktop y móvil para revisar vencimientos, registrar documentos, y controlar costos.

**Contexto de uso**: Oficina (desktop) y campo (móvil). Necesitan información rápida y accionable — "¿Qué vence esta semana?" — no pantallas decorativas. La app se usa con urgencia real: un SOAP vencido significa multas o no circular.

**Job to be done**: Mantener la flota al día con cero sorpresas. Saber qué documento vence cuándo, cuánto se ha gastado, y tener todo documentado y accesible.

## Brand Personality

**3 palabras**: Confiable, Técnico, Eficiente.

**Tono**: Profesional sin ser frío. Preciso sin ser denso. La interfaz transmite control y confianza — el usuario siente que su flota está bajo control.

**Emociones objetivo**: Confianza ("todo está al día"), Control ("veo exactamente qué pasa"), Calma ("nada vencido que no sepa").

## Aesthetic Direction

**Referencia principal**: cmdspa.com — dark mode tech-forward con cyan (`#00eaff`) como acento, tipografía Orbitron para display, Exo 2 para body, neural background animado.

**Dirección visual**: Panel de control industrial refinado. Información densa pero legible. Dark mode nativo (no adaptado). El cyan CMD es el acento, no el protagonista — el protagonista es la data.

**Anti-referencias**:
- ❌ NO AI genérico: nada de cyan brillante sobre negro puro tipo ChatGPT interface. El cyan es sutil, con tinientes azulados en los neutrales.
- ❌ NO startup pastel: nada de gradientes suaves, colores pasteles, o estética "cute".
- ❌ NO enterprise gris: nada de SAP/Oracle con formularios grises aburridos.

**Tema**: Dark mode como default, light mode disponible. Ambos con neutrals tintados hacia el azul brand (nunca gris puro).

## Design Principles

1. **La data es la protagonista** — cada pixel debe servir para entender el estado de la flota. Sin decoración que no comunique información.

2. **Menos es más, pero denso** — priorizar densidad informativa sobre espacio en blanco. Un admin de flota prefiere ver 11 vehículos con todos sus datos en una pantalla que 3 cards gigantes con emoji.

3. **Feedback inmediato** — cada acción debe tener respuesta visual instantánea. Toast, animación de entrada, count-up de KPIs. El usuario nunca duda si algo se guardó.

4. **Consistencia sistemática** — design tokens CSS para todo. Misma paleta, misma tipografía, mismo espaciado. Dark/light con la misma estructura, solo cambiando los valores de los tokens.

5. **Accesibilidad no negociable** — WCAG AA mínimo. Touch targets 44px, labels en todos los inputs, aria-live en feedback dinámico, focus-visible consistente, respeta reduced-motion.

## Design Tokens (referencia)

### Dark theme (default)
- Background: `#0e1320` (azul-negro)
- Surface: `#161d2e`
- Brand accent: `#00eaff` (cyan CMD)
- Brand text: `#00eaff`
- Text primary: `#e8ecf4`
- Text secondary: `#aab4cc`
- Font display: Orbitron
- Font body: Exo 2
- Font mono: JetBrains Mono (patentes, VIN)

### Light theme
- Background: `#eef2fa` (blanco azulado)
- Surface: `#ffffff`
- Brand accent: `#0066cc` (azul oscuro para contraste AA)
- Text primary: `#0f1729`

### Estados (ambos temas)
- Rojo (vencido): `#ff5c5c` / `#dc2626`
- Ámbar (por vencer): `#fbbf24` / `#b45309`
- Verde (al día): `#34d399` / `#15803d`
